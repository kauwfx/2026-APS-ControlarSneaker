# 4.2.1 Levantamento de Requisitos

## 1. Como os requisitos foram levantados

Os requisitos do ControlarSneaker foram levantados a partir da descrição do problema apresentada pelo cliente, Kauê, proprietário e vendedor da loja, e da análise de como os pedidos e as entregas são controlados atualmente.

Foram consideradas principalmente as dificuldades relacionadas ao registro manual dos endereços, ao controle dos pedidos e aos atrasos nas entregas. Também foram utilizados como base o propósito, o objetivo, o escopo e as características principais definidos na seção 4.1.
  Ainda é necessário confirmar com o cliente quais informações são obrigatórias no cadastro do cliente e do endereço, quais dados devem ser registrados em um pedido e quais regras serão utilizadas para alterar o status das entregas.

## 2. Da fala à necessidade

| #  Fala do cliente,Classificação,Necessidade por trás 

| F1 | "Recebo os pedidos pelo site, mas preciso anotar e controlar os endereços e as entregas manualmente." (Kauê, proprietário e vendedor) | Necessidade | Centralizar o registro dos pedidos, endereços e informações de entrega. |
| F2 | "Às vezes os dados ficam incompletos ou ocorrem atrasos." (Kauê, proprietário e vendedor) | Necessidade | Manter os dados necessários para a entrega registrados e acompanhar o andamento dos pedidos. |
| F3 | Necessidade implícita a confirmar com o cliente: acompanhar os pedidos que ainda precisam ser entregues, suas datas e seus endereços. | Necessidade implícita | Organizar os pedidos pendentes para facilitar o acompanhamento das entregas. |

## 3. Histórias de usuário

| # | História de usuário | Veio de:
| HU01 | Como Vendedor/Administrador, quero cadastrar clientes com seus endereços e dados de contato, para ter as informações necessárias para realizar as entregas. | F1 |
| HU02 | Como Vendedor/Administrador, quero registrar pedidos de tênis vinculados aos clientes, para manter cada pedido relacionado ao cliente correto. | F1 |
| HU03 | Como Vendedor/Administrador, quero organizar e listar os pedidos pendentes por data e endereço de entrega, para saber quais entregas precisam ser realizadas e onde devem ser entregues. | F2 e F3 |
| HU04 | Como Vendedor/Administrador, quero atualizar o status de cada entrega, para acompanhar o andamento do pedido até sua conclusão. | F2 |
| HU05 | Como Vendedor/Administrador, quero consultar o histórico de entregas de um cliente, para verificar as entregas já realizadas para ele. | Escopo da 4.1 |

## 4. Requisitos funcionais

| # | Nome,  Requisito, Veio de:

| RF01 | Cadastrar cliente | O sistema deve permitir que o Vendedor/Administrador cadastre clientes com seus endereços e dados de contato. | HU01 |
| RF02 | Registrar pedido | O sistema deve permitir que o Vendedor/Administrador registre pedidos de tênis vinculados aos clientes. | HU02 |
| RF03 | Listar pedidos pendentes | O sistema deve listar os pedidos pendentes por data e endereço de entrega. | HU03 |
| RF04 | Atualizar status da entrega | O sistema deve permitir que o Vendedor/Administrador atualize o status de cada entrega. | HU04 |
| RF05 | Consultar histórico de entregas | O sistema deve permitir que o Vendedor/Administrador consulte o histórico de entregas de um cliente. | HU05 |

## 5. Requisitos não funcionais

| # | Categoria, Requisito,Veio de:

| RNF01 | Desempenho | A visualização das entregas pendentes deve responder em menos de três segundos.
| RNF02 | Acesso | O acesso e as alterações de status devem ser restritos ao perfil cadastrado de Administrador.
| RNF03 | Dispositivo | O sistema deve funcionar via navegador e ser acessível por computador ou dispositivos móveis. 
## 6. Conferência com a 4.1

| Item do escopo da 4.1  Requisito(s) relacionado(s)
|---|---|
| O sistema cadastra clientes com seus endereços e dados de contato. | RF01 |
| O sistema registra os pedidos de tênis vinculados aos clientes. | RF02 |
| O sistema organiza e lista os pedidos pendentes por data e endereço de entrega. | RF03 |
| O sistema atualiza o status de cada entrega. | RF04 |
| O sistema permite consultar o histórico de entregas realizadas por cliente. | RF05 |

Todas as histórias de usuário possuem pelo menos um requisito funcional correspondente:

- HU01 → RF01
- HU02 → RF02
- HU03 → RF03
- HU04 → RF04
- HU05 → RF05

Todos os requisitos funcionais possuem uma origem definida nas histórias de usuário ou no escopo da seção 4.1. Os requisitos não funcionais foram definidos a partir das características principais do sistema.

A conferência entre a seção 4.2.1 e a seção 4.1 não identificou nenhum item do escopo sem requisito correspondente.

❓ Antes da versão final, ainda devem ser confirmadas com o cliente as regras específicas de cadastro, pedido e alteração de status que não foram detalhadas na seção 4.1.
