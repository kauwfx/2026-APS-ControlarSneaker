# 4.2.3 Modelagem de Classes

## Dos substantivos às classes

As classes saem dos substantivos. A fonte principal é o fluxo de Registrar pedido, especificado na 4.2.2. Cada coisa que o ator informa ou que o sistema confirma é uma coisa que o sistema precisa lembrar. A segunda fonte é a lista de requisitos da 4.2.1. O que aparece nas duas vira classe com mais confiança.

Nem todo substantivo vira classe. Três filtros: o que é detalhe de outra coisa vira atributo (o telefone é detalhe do cliente). O que é interface não entra (tela, botão, relatório). O que está fora do sistema também não.

| Substantivo | De onde veio | Vira | Por quê |
|---|---|---|---|
| cliente | passo 1 do fluxo, HU01, RF01 | classe **Cliente** | o sistema guarda quem ele é, seu endereço e dados de contato para entregas |
| vendedor / administrador | ator da 4.2.2, pré-condição, RNF02 | classe **Usuario** e classe **Vendedor** | o sistema precisa saber quem é o usuário autenticado que registra pedidos e atualiza status |
| nome, telefone, endereço | passo 2 do fluxo ("apresenta os dados cadastrados"), RF01 | atributos de **Cliente** | são os detalhes cadastrais necessários para contato e envio do tênis |
| pedido | passo 3 e 7 do fluxo, HU02, RF02, RF03 | classe **Pedido** | é a venda registrada: vincula o cliente aos itens e à sua entrega |
| produto / sneaker | escopo da 4.1, HU02, RF02 | classe **Produto** | o tênis comercializado pela loja que compõe o pedido |
| entrega / status | passo 5 e 6 do fluxo, HU04, RF04, RF05 | classe **Entrega** | o registro com endereço, status, datas e histórico de transporte |
| dados da entrega | passo 5 ("informa os dados da entrega") | atributos de **Entrega** | são detalhes como endereço final e status da entrega, não algo isolado |
